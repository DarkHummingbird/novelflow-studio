# NovelFlow Studio · 用户需求场景

> 这份文档回答三个问题：**谁会用**、**在什么时刻用**、**用完得到了什么**。
> 每个场景都标注了「当前实现能否支撑」——已实现 ≠ 好用，缺口单独列出，不粉饰。

---

## 0. 一句话定位

> 给「短篇付费网文」这条产业链上的人，把**卡点之后的 5,000–8,000 字**从"靠灵感手搓"变成"按商业结构流水线产出"，并且**产出的每一段都能被验收到门禁级别**。

核心不是"让 AI 写小说"，是**让"卡点兑现"这件事可交付、可复用、可验收**。

---

## 1. 用户分层

| 层 | 是谁 | 痛点强度 | 付费意愿 | 使用频次 |
| --- | --- | --- | --- | --- |
| **A. 短篇作者 / 日更写手** | 番茄短故事、知乎盐言、公众号付费图文的个人作者 | ★★★★★ | 中（订阅/买断） | 每天 |
| **B. 推文 / 投流工作室** | 抖音推文号、短剧前置素材、批量拆解爆款 | ★★★★★ | 高（团队采购） | 每天批量 |
| **C. 代写 / 接单个体** | 闲鱼、淘宝、小红书接"求后续" | ★★★★ | 中（按单） | 每周数单 |
| **D. 编辑 / 内容负责人** | 工作室审稿、外包验收 | ★★★ | 高（买的是标准） | 每周 |
| **E. C 端读者** | 被付费墙卡住的追更者 | ★★★★（情绪强） | 低（一次性） | 偶发 |
| **F. 写作教学 / 拆解者** | 写作课、社群、内容拆解博主 | ★★ | 低-中 | 每周 |

**当前实现最匹配的是 A 和 C**：单人、本机、有明确前文和交付形态。
**B 需要批量能力（缺口，见 §5）**，**D 只需要报告那一半**，**E 更像获客入口而非付费主体**。

## 2. 核心场景

### S1｜C 端读者：被卡在付费墙后面的那 3,000 字

**触发时刻**
晚上 11 点刷到一条推文视频，看了三分钟录屏，正到「我抬手，把那份鉴定报告拍在他脸上——」，视频结束，提示"点击左下角阅读原文"。跳过去要付费，或者干脆搜不到后续。

**真实需求（按优先级）**
1. 立刻知道"拍下去之后发生了什么"（延迟一秒都会流失）
2. 结局要闭环，不能吊着（"付了钱还烂尾"是这类内容最大的投诉）
3. 手机上能存下来慢慢看

**用产品的路径**
粘贴前文 → 一键续写（紧凑版 5,500 字）→ 读 / 导出 TXT 存手机。全程 3–5 分钟。

**成功判据**
前 800 字必须给出结果；终段必须有清算和金句；不需要注册、不上传。

**当前限制（重要）**
- 不配模型 Key 时是**仿真引擎**，只能看清结构，不能当正文读 → 这个场景要成立，必须能接真模型（BYOK 或本地代理）。
- 付费意愿低：更适合作为**免费获客入口**（引流到作者/工作室版），而不是订阅主体。

---

### S2｜短篇作者：今天这篇 7,500 字，明天还有一篇

**触发时刻**
手上有一篇 4,000 字开篇，停在付费卡点。平台征稿要求单篇 8,000–12,000 字。晚上 9 点开始写，写到凌晨还在第二段。

**真实需求**
1. 别被单次输出的字数上限截断（写到 2,000 字突然停住）
2. 别注水、别复读、别满屏"嘴角勾起一抹弧度"
3. 某一段不满意时，能只改那一段，不要全篇重来
4. 产出要能直接投稿（结构、字数、结尾都过线）

**用产品的路径**
载入前文 → 选字数档位（紧凑/标准/加长）→ 改四拍蓝图（尤其"转"拍）→ 启动续写 → 门禁 REJECT 时自动带指令返工 → 对不满意的段落发起局部重写 → 导出 MD（含门禁报告）。

**成功判据**
字数达标 ≥85%、前 800 字兑现、10-gram 重复率 <18%、终段金句成立；改稿只动一段。

**当前限制**
- 文风复刻靠提示词，不是微调模型；仍要 1–2 小时人工润色。
- 长篇（>6,000 字前文）走 Arc Unit，但**没有伏笔账本**，跨单元容易吃书。

---

### S3｜推文 / 投流工作室：一条前文，测五种走向

**触发时刻**
一天要出 5–10 条推文素材，同一个卡点要测"直接复仇 / 身份掉马 / 幕后黑手另有其人"哪个完读率高。

**真实需求**
1. 同一前文，不同走向各出一版（而不是重写五遍）
2. 版本之间可比对（字数、结构、金句）
3. 团队里新人照着 SOP 也能出稿
4. 结果可留档、可交接

**用产品的路径**
复制作品 → 改「续写走向与爽点指令」（有快捷 chips）→ 各跑一版 → 每版导出契约 JSON 留档 → 人工挑优。

**成功判据**
同一前文能稳定产出多个走向版本；每版都有可读的质检报告。

**当前限制（P1 缺口）**
- **没有批量队列**，只能一条条跑；**没有版本对比视图**，要靠导出 JSON 人工比。
- 这是"工作室愿意付钱"和"个人偶尔用"的分水岭，建议优先补。

---

### S4｜代写 / 接单：客户给了前文，48 小时交稿

**触发时刻**
接到一单"求后续"，客户把付费前的部分发过来，说"就照这个风格写完，别太 AI"。

**真实需求**
1. 初稿要快（决定能不能接这单）
2. 客户提修改意见后能精准改（"打脸再狠一点""多加两句宾客倒戈"）
3. 改坏了能退回去（改稿最容易翻车）

**用产品的路径**
粘贴前文 → 生成蓝图 → 续写 → 局部重写（把客户原话填进微调框）→ 不满意就回滚快照 → 导出 TXT 交稿。

**成功判据**
一次成稿 + 1–2 次定点修改；每次改前有快照可回滚。

**当前限制**
- 无报价/交付管理（不是本产品职责）。
- **版权合规是使用者责任**：产品不内置任何原作库，全部靠用户粘贴。

---

### S5｜编辑 / 内容负责人：把"我觉得不行"变成"第 3 条门禁没过"

**触发时刻**
外包作者交稿，编辑觉得"前面太拖""结尾没劲"，但说不清标准，来回改三版。

**真实需求**
1. 可解释的验收标准（不是感觉）
2. 每条不合格都要指向具体位置和原因
3. 报告能随稿一起存档

**用产品的路径**
打开「门禁报告」页 → 六道门禁逐项 PASS/FAIL + 明细（字数、实体命中、人称计数、重复率、金句长度）→ 导出的 MD 末尾自动附报告。

**成功判据**
沟通成本从"我觉得"变成"字数 1,422/2,025，第 1 条门禁没过，请补足动作交锋"。

**当前限制**
门禁是**启发式**，能挡住明显问题（拖、水、套话、无兑现），**不能替代人的品味判断**；它是沟通依据，不是终审。

---

### S6｜写作教学 / 拆解：为什么卡点要停在这里

**触发时刻**
写作课要讲"30% 付费卡点怎么设计""为什么前 800 字必须兑现"，需要可演示的样本。

**真实需求**
1. 能看到卡点位置判定（为什么被识别成"憋屈→反击"）
2. 能看到四拍结构怎么落到具体段落
3. 能看到底层提示词（方法论是显性的，不是玄学）

**用产品的路径**
载入示例样本 → 看诱饵诊断卡片 → 看四拍蓝图 → 切「架构师视图」看 System Prompt / 契约 / 实时载荷。

**当前限制（P1 缺口）**
- 没有「拆解模式」：现在想看别人的爆款结构，必须走一遍完整续写。理想形态是"粘贴任意前文 → 只输出诊断报告，不写正文"。

---

### S7｜同人 / 二创续写（边缘场景，不建议主打）

**触发时刻**
原作断更/烂尾，读者想自己续一段。

**风险**
平台规则与版权界定；产品本身是纯本地工具，数据不上传，但**内容责任在使用者**。

## 3. 一个典型用户的完整一天（S2 · 作者）

| 时间 | 动作 | 产品在做什么 |
| --- | --- | --- |
| 09:10 | 刷到一篇爆款推文，复制前文 | — |
| 09:30 | 粘贴、载入，确认 3,364 字 / 黄金卡点期 | Agent01 清洗 + 体量路由 + 诱饵分类 |
| 09:35 | 生成四拍蓝图，把第 2 段「转」改成"身份掉马全网直播" | Agent02 出蓝图，可逐拍编辑 |
| 09:40 | 启动续写，去泡咖啡 | Agent03 滑动窗口撰写，Agent04 门禁 |
| 09:48 | 回来看：第 2 段门禁 REJECT（字数不足 1,012/3,000）自动返工，第 2 次通过 | 自动返工 + 日志留痕 |
| 09:55 | 第 1 段打脸戏不够狠 → 局部重写（改前自动快照） | 只重写该段 + 重跑门禁 |
| 10:10 | 导出 MD（含门禁报告），开始人工润色 | — |
| 12:00 | 投稿 | — |

**价值**：把 4 小时的机械劳动压到 40 分钟，把省下的时间还给"润色和设计爽点"——那才是作者真正的护城河。

## 5. 明确不适用的场景（劝退清单）

1. **20 万字以上的长篇连载**：Arc Unit 能滚动，但没有伏笔 OPEN/RESOLVED 账本，跨单元会吃书。
2. **多人协作 / 团队共享稿件**：无后端、无账号，数据在各自浏览器里。
3. **要求严格世界观一致性的复杂作品**（多线、硬科幻设定）：当前上下文窗口是"摘要 + 1,500 字切片"，撑不住。
4. **希望零人工直接发布**：仿真模式是给"看结构"用的；真模型产出也需要 1–2 小时润色。
5. **需要版权合规担保的批量二创**：工具不内置原作库，责任在用户。

## 6. 优先级建议

| 优先级 | 做什么 | 理由 |
| --- | --- | --- |
| **P0** | 真模型开箱即用（内置一键代理/免配置）、门禁误杀率调优 | 决定 S1–S4 能不能真正落地 |
| **P1** | 批量多走向 + 版本对比视图；拆解模式 | S3（最愿意付钱的群体）和 S6 的入口 |
| **P2** | 账号/云同步/团队、配额计费、真实视频 OCR、伏笔账本 | 需要后端，属于"卖订阅"的前提 |

## 7. 怎么验证这些场景是真的（不是我自己想的）

用这 6 个问题去问 3 个真实用户，就能证伪：

1. 你上一次"卡点之后写不出来"是什么时候？最后怎么解决的？（验证 S2 痛点强度）
2. 一篇 8,000 字的稿，从卡点到交稿你现在要几小时？愿意为"压到 1 小时"付多少钱？（验证付费意愿）
3. 你用过通用 AI 续写吗？最不能忍的是哪一点？（验证"门禁"是否是真需求）
4. 你的稿子被编辑打回过吗？理由说过得清吗？（验证 S5）
5. 同一个卡点，你会写几个走向？怎么挑？（验证 S3 的批量需求）
6. 如果这个工具明天消失，你会难受还是无所谓？（验证留存）

**可测指标**（产品埋点应在本地统计、不上传）：
- 首稿门禁一次通过率（目标 ≥60%）
- 从粘贴到导出的耗时（目标 ≤15 分钟）
- 每篇平均局部重写次数（目标 ≤2）
- 归档导出率（判断用户是否真的在"保管成果"）
