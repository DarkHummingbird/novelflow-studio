# 术语对照表

界面已经全部改成大白话。这份表用来对齐「旧说法 / 界面现在的说法 / 代码里的名字」，方便开发和用户之间沟通。

| 旧说法（行话） | 界面现在写 | 代码 / 文档里的名字 | 解释 |
| --- | --- | --- | --- |
| 门禁、六道门禁 | **质检 / 六项检查** | `evaluateGates`、`GateResult` | 每段正文的六条硬性检查，代码判，模型不参与打分 |
| 门禁报告 | **质检结果 / 质检报告** | 同上 | 六条检查逐条 PASS/FAIL + 原因，随稿一起导出 |
| 诱饵、六大诱饵 | **悬念类型** | `classifyBait`、`bait_type` | 卡点句属于哪一类悬念：憋屈→反击、困境→解法、谜题→答案、关系→临界、死亡→降临、真相→反转 |
| 卡点 | **付费点** | `ending_anchor` | 免费内容结束、开始收费的那一句 |
| 四拍、四拍蓝图 | **分段大纲 / 四步大纲** | `segment_outlines`、`beats` | 每段分「开端 / 承接 / 反转 / 收尾」四步 |
| 起承转合 | **开端 / 承接 / 反转 / 收尾** | `qi / cheng / zhuan / he` | 同上，只是换了不拗口的说法 |
| 蓝图 | **大纲** | `Agent2Payload` | 写作前的主干设计 |
| 体量路由 | **按字数自动选模式** | `resolveLengthTier` | 前文多少字决定用哪种写法 |
| 蓄势期 / 黄金卡点期 / 长篇滚动期 | **短前文 / 标准卡点 / 超长篇** | `EARLY_SETUP_… / STANDARD_… / LONG_FORM_…` | 三个字数区间 |
| Arc Unit | **单元** | `ARC_UNIT_WORDS` | 超长篇里每 3,500 字一个小高潮 |
| 微步长接力 | **自动补齐** | `writeWithLLM` 续写循环 | 一次写不完就接着写，避免被输出上限截断 |
| 滑动窗口 | **前文记忆** | `contextWindow` | 写第 N 段时带上最近正文和摘要 |
| Story Bible | **人物与文风设定** | `story_bible` | 人物卡、人称、文风特征 |
| 文风指纹 | **文风特征** | `style_fingerprint` | 平均句长、对话比例、语气词 |
| 契约 / 载荷 / Schema | **数据格式 / 这一轮的数据** | `Payload`、`OutputContract` | 每一步之间传递的数据结构 |
| 仿真引擎 | **模板演示**（仅开发可见） | `simulate.ts` | 不接模型时用模板拼句子，只用于测试，产品路径默认关闭 |
| 快照 | **存档 / 版本历史** | `SnapshotRecord` | 某个时刻的整份作品副本，可回滚 |
| 归档 | **备份** | `buildArchive` | 把所有作品和存档打包成一个 JSON |
| 返工 | **重写** | 门禁 REJECT 后的重试 | 没过检查就带着修改意见重写这一段 |
| 兜底 | **备用方案** | fallback | 模型失败时用的降级逻辑 |
| 归一化 | **格式校正** | `coerceAgent2` | 模型输出不守格式时纠正它 |
| BYOK | **自带模型** | `ApiConfig` | 自己填模型服务的 Key |
| 架构师视图 | **开发视图** | `WorkspaceMode.architect` | 给开发看提示词和数据的那一层 |
| 口径 | **字数算法** | `countWords` | 字数怎么数（不含空格的字符数） |
| 主笔 | **写正文** | Agent 03 | 负责写的那一步 |
| 逐拍修改 | **逐段修改** | 大纲编辑 | 改大纲里的某一步 |

## 界面上的四步

| 界面 | 旧叫法 | 做什么 |
| --- | --- | --- |
| **第 1 步 · 读前文** | Agent 01 · 卡点摄取 | 清掉平台噪音，算出字数，找到付费点 |
| **第 2 步 · 出大纲** | Agent 02 · 诱饵与蓝图 | 判断悬念类型，出分段大纲 |
| **第 3 步 · 写正文** | Agent 03 · 滑动主笔 | 按大纲一段段写，不够长自动补齐 |
| **第 4 步 · 做质检** | Agent 04 · 六道门禁 | 六条检查，没过就带意见重写 |
